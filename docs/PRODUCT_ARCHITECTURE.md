# 投标助手产品架构

## 1. 产品定位

投标助手是一套面向企业投标团队的全过程智能投标工作台。用户可主动创建投标项目并上传招标文件，也可从招标机会完成初筛、人工确认并携带文件转入项目，再通过招标解析、资格研判、投标事项整理、知识匹配、标书编制、智能检查、人工质量审核和文件交付完成投标文件。

产品核心不是“一键生成一篇标书”，而是解决以下问题：

1. 招标文件是否看全、看准。
2. 企业是否具备投标资格，是否存在资格阻断问题。
3. 每一条招标要求和评分点是否都有响应内容及证明材料。
4. 标书内容是否来源可靠、前后一致、符合指定格式。
5. 最终投标文件是否完整、经过人工确认并可安全交付。

## 2. 产品范围

### 当前包含

- 首页
- 招标机会
- 投标项目
- 知识库
- 投标台账
- 管理中心

### 当前不包含

- 真实网站采集、后台定时执行及真实模型评估
- 销售 CRM、合同履约等外围经营管理

产品入口包括“新建投标项目”和“机会确认投标后转入投标项目”。

## 4. 投标项目工作台

投标项目承载正式投标工作。机会确认投标后可转入，原有上传建项入口继续保留。进入具体项目后，采用以下项目内页签：

两种建项入口在创建后统一进入招标文件页并自动解析，共用项目数据、文件清单及后续阶段。直接上传时项目信息待解析；机会转入时带入公告基本信息、负责人及所选文件，并独立保留转入时的初评、公告和规则版本、人工确认记录。项目使用自己的解析与标书内容，正式文件版本和人工审核关口保持一致。来源更新只提示影响，不自动覆盖已编制正文；机会中的项目入口按当前阶段定位。

项目数据按项目编号保存，文件更换及补传跨页保留，文件变更后需重新解析。机会页刷新恢复默认时，同步清理本轮关联项目的编制和审核会话并内部留存，普通导航与项目页刷新不重置；其他项目、规则、来源及采集记录保留。

1. **招标文件**：管理原始招标文件、附件、补遗和澄清文件，展示解析过程、文件版本和差异。
2. **解析结果**：集中展示项目核心信息、资格与材料准备度、全部投标事项、响应处理建议、知识材料匹配结果和来源原文；用户处理不满足事项、确认综合结论后生成投标文件。
3. **标书编制**：按招标目录生成和编辑技术标、商务标，保存联合版本，并在页面内完成智能检查、问题整改和复检。
4. **质量审核**：人工只读查看已通过智能检查的技术标、商务标送审版本；审核前可退回标书编制，审核通过后开放交付归档，质量审核页隐藏退回操作并保留已通过状态。
5. **交付归档**：展示人工审核通过状态，保留退回修改入口；版本确认后导出 Word/PDF、生成文件包并归档。

### 标书版本规则

- 编辑过程自动保存当前工作内容；用户点击编辑器“保存”时，同步更新当前版本，版本号不变。
- 用户主动“另存为版本”时，基于当前技术标和商务标生成新的联合版本并切换为当前版本，已有历史版本保持不变。
- 版本号由系统按 `V1.0.x` 顺序生成，版本递增与智能检查次数相互独立。
- 提交智能检查时自动保存当前技术标和商务标，并基于当前版本建立检查快照；智能检查不要求先另存新版本。
- 智能检查、人工质量审核和正式交付必须绑定具体标书版本及检查批次；当前版本修改后，已有检查结果失效并需要重新检查。
- 审核退回或交付退回后保留原版本、检查记录和审核结论；修改可继续保存在当前版本，需要保留阶段节点时再另存为新版本。
- 正式交付只使用一个人工审核通过版本；项目归档保留全部人工版本，知识库历史标书默认只沉淀正式交付版本。

## 5. 招标解析核心域

智能解析至少覆盖以下十个业务域：

| 解析域 | 关键输出 |
| --- | --- |
| 投标人须知前附表 | 截止时间、开标时间、保证金、有效期、签章、密封、递交方式等关键事项 |
| 资格审查/资格预审 | 资格准入清单、证明材料、企业匹配结果和缺口 |
| 投标人不得存在的情形 | 负面条件核查清单和所需承诺材料 |
| 投标文件组成 | 最终投标文件目录与完整性检查清单 |
| 评标办法 | 技术、商务、价格评分矩阵，分值、标准和响应策略 |
| 商务要求 | 商务条款响应事项清单 |
| 商务偏离表 | 商务要求、响应情况、偏离说明和人工确认状态 |
| 技术要求 | 功能、参数、实施、服务、交付和验收要求 |
| 技术偏离表 | 技术要求、响应参数、证明材料、偏离情况和人工确认状态 |
| 投标文件格式 | 指定章节、表格、承诺函、签章、页码、装订和文件命名要求 |

每条解析结果应保存：来源文件、页码/条款、招标原文、分类、重要性、强制性、分值、需要完成的内容、AI 置信度、人工确认状态。

## 6. 投标事项

解析结果页以投标事项承载招标要求、处理建议和知识材料匹配结果。每一条投标事项包含：

- 分类和编号
- 招标原文及来源位置
- 资格硬门槛、评分项、商务要求、技术要求或文件交付要求
- 分值和评分标准
- 响应处理建议
- 知识材料与证明证据的匹配情况
- 当前结论和问题状态
- 用户补充的处理说明与附件

当前页面状态统一为：已满足、不满足、AI处理。

## 7. 知识库架构

知识库保留多分类入口和左侧二级导航，方便按业务对象查找资料；除人员档案外，其他分类统一使用同一套资料列表、上传解析、详情和归档逻辑。分类只负责归类、筛选和限定 AI 检索范围，不再为每个分类设计独立的必填业务表单。知识库只维护资料，不设置审核流程。

### 企业资料

1. **企业基础资料**：营业执照、公司简介、财务、信用和开户信息。
2. **企业资质证照**：行业资质、体系认证、荣誉、知识产权和许可证。

### 人员资料

3. **人员档案**：先新增人员或批量导入人员名单，再批量上传资质资料，由 AI 解析姓名、证书信息并自动关联人员；未匹配和低置信度结果在导入前集中确认。
   - 证书与资质：以导入证书为入口，由 AI 自动提取证书名称、编号、机构和期限，用户可以修正解析结果。
   - 项目经历：以项目经历证明材料为入口，由 AI 提取项目、角色和参与期间。
   - 证明材料：以简历、学历和劳动关系等附件为入口，由 AI 提取相关信息。
   - 引用记录：记录人员档案被投标项目和标书章节引用的情况。

人员档案只按“在库、已归档”维护生命周期。在库人员可以编辑或归档，已归档人员可以查看或删除。人员详情中的证书与资质、项目经历和证明材料统一显示来源文件图标、资料名称和当前相关内容，并提供编辑、归档操作；已归档的关联资料进入统一的“已归档资料”列表，归档后可以删除。

人员档案不包含人员档期、项目占用或时间冲突管理。

### 项目经验

4. **业绩案例**：合同、验收证明和项目说明等历史项目资料。
5. **历史标书**：归档既往项目的技术标、商务标和最终交付附件，支持按项目类型查找和授权复用；知识库不承担复盘、得分、评委反馈或失分分析。

### 内容素材

6. **产品与技术方案**：产品介绍、功能、架构、实施、运维和安全方案。
7. **商务素材**：服务、保密、廉洁、售后和履约承诺。
8. **模板与格式**：投标模板、偏离表、简历、承诺函和封面目录模板。
9. **图表素材**：架构图、流程图、拓扑图、截图和组织架构图。

普通知识资料统一具备：名称、分类、类型、标签、摘要、说明、来源文件、AI 解析状态、最近更新和引用记录。上传资料后由 AI 自动提取通用信息和分类相关结构化信息；证书编号、发证机构、有效期限、项目金额等内容仅在原始资料中实际存在时解析和展示，不作为通用必填字段。

普通资料只保留简单的生命周期管理：在库资料由“已入库”和“解析中”组成，归档后进入独立的“已归档”列表。知识库不设置审核状态，也不设置“解析失败”状态；AI 未识别到有效结果时，直接展示空白基础属性，由人工补充后正常入库。编辑资料时可以修改属性或替换来源文件并重新解析，不再提供独立的“上传新版本”入口。在库资料可查看、编辑和归档；已归档资料可查看或永久删除，删除操作仅对已归档资料开放。知识库不维护资料使用范围或查看权限字段。

有效期是独立于资料生命周期的业务维度，只保留“长期有效”和“固定有效期”两种类型：没有明确截止日期的资料统一视为长期有效，证照、人员证书以及需要定期更新的证明资料统一按固定有效期维护。系统根据 AI 提取的截止日期按 60 天口径计算“有效、临期、已过期”等状态，并在总览指标、有效期预警 Tab、左侧分类目录、资料列表和详情中集中提醒。已过期资料仍保留在库并提示通过编辑替换文件；已归档资料保留有效期记录，但不计入当前预警数量。

知识库中代表具体文件的图标统一复用公共文件格式图标，根据真实扩展名显示 PDF、Word、Excel、PPT、压缩包、SVG、图片、OFD 等格式；人员头像和上传、编辑、归档等操作图标继续表达人员或操作语义，不与文件格式图标混用。

## 8. 标准业务流程

前置机会流程：来源与规则配置 → 页面内计划/手动采集演示 → 公告去重与更正关联 → 条件筛选与可解释初评 → 人工确认（确认投标、放弃机会）→ 确认负责人及 PDF/Word 主文件 → 转入投标项目。

每条机会仅保留首次采集入库的网站及对应公告链接。跨网站重复采集计入当前网站的去重数量，不追加或替换机会来源；旧多来源记录保留原数组首个来源，列表、详情和来源查询采用同一口径。更正公告继续关联，历史评分、材料快照和处理记录不改写。

机会初评分用于匹配排序，不等于评标得分或中标概率。原型以预设案例展示分数和依据，保留最低入库分数配置，不开放权重或命中逻辑配置；未知项显示待核验，不视为已满足。文件获取、报名、投标截止分别判断，暂停、终止、截止阻止推进。公告更正或规则变化保留原决定和记录，通过同一人工确认入口重新确认，转项目绑定最新确认公告版本，重复操作不会重复建项。

招标机会静态原型包括列表、详情、规则、来源和采集记录；默认来源为华润守正采购交易平台、深圳政府采购智慧平台、知了标讯。网站入口与用户提供的完整示例公告链接分别保留；内置公告及附件为虚构业务数据，与用户链接指向的真实公告不对应，真实采集能力仍待核验。业务界面统一采用正式产品文案，不显示原型、演示、模拟等实现说明，不展示演示账号、密码或验证码；内置公告编号、文件名、联系人等不带演示标记。业务文案清理仅替换已知系统文案；默认样例恢复按下述刷新规则执行，配置和重置前记录保留。实现边界保留在开发文档中：计划只在模块打开时模拟执行，本地保存机会、审核及项目关联，上传文件仅保存元信息，未接入真实网站采集、模型评估或文件解析。转入后的文件与解析摘要使用该机会内容，不复用其他项目标书。

初评分析按留存的公告、业务规则及评估时间展示判断结论，预算、地区、准备时间分别说明符合、不符或信息未披露，不再只显示已识别。新初评和重新初评的准备时间统一按评估时至投标截止计算，获取与报名截止独立展示参与风险；旧评分快照不重算，旧准备时间判断按当时口径保留。资格条件不冒充企业已满足，不改变人工状态。过期初评分在详情顶部标为上次初评分，并相邻显示评估时间、公告版本和规则版本；原分数不随期限实时重算。采用规则的折叠快照复用结构化业务字段，补全业务方向，不混入采集周期和回溯安排。详情保留概况事实、初评判断、公告附件和处理历史的分工，当前关注合并重复项；人工确认展示最多三项当前关键关注。转入负责人默认匹配当前用户，无法匹配时必须主动选择；附件有正文时预览，有来源文件地址时直接查看来源文件，否则查看文件信息并保留来源公告入口。

机会列表来源筛选与采集记录一致按来源 ID 匹配，10 个及以下使用普通下拉，超过 10 个支持搜索；选定或清除立即查询，未选定的自由输入仅在查询或 Enter 时执行。重名来源用域名辅助区分，改名后 ID 查询仍有效，旧名称仅在证据唯一时恢复到原 ID；来源配置移除时从已留存名称和入口回退展示，不误标来源已停用。来源编辑保存校验打开时的配置，其他页面修改名称、类型、入口、栏目、启停或登录凭据后阻止旧表单覆盖；最近检查、登录续期和采集进度变化不误触发配置冲突。冲突时保留当前输入，主动载入最新配置时合并本次修改并要求再次核对，不持久化密码草稿。

准备时间的新初评与重新初评统一按评估时至投标截止计算，文件获取、报名期限独立提示参与风险；旧评分快照不重算，旧准备时间判断按当时口径保留。临期卡片与已放弃、已转项目筛选互斥，其他查询条件保留；卡片使用简短说明，完整统计范围放注释浮层。转项目过期弹窗载入最新内容时保留有效负责人、补传文件及选择，最新公告文件更新、移除或同名冲突须明确提示并重新选择，不沿用失效主文件；草稿仅在本页内存中保留，不影响刷新恢复默认。人工确认及转项目弹窗实时更新获取、报名截止风险，不增加核验步骤，不改人工决定或历史评分。来源检查采用检查通过、检查失败、待检查，与启停、登录状态分开；失败为红色，待检查或登录失效为橙色。采集反馈区分全部失败和部分失败，成功概要统一为公告采集及处理完成，不暗示更正公告已重新初评。

```text
  → 人工查看技术标、商务标送审版本
  → 人工审核通过
  → 生成Word、PDF及交付文件包
  → 全部标书版本归档、投标台账与知识沉淀
```

招标机会当前交互边界补充：转项目弹窗校验附件清单、版本、大小等变化，即使正文公告版本未变也使旧提交失效；仅附件变化不额外改变人工确认。重新载入沿用有效负责人、补传文件和选择，冲突文件重新选择。当前时效风险从结构化参与时间动态生成，旧倒计时或尚未开始描述失效后不再展示为当前风险；其余业务要求、原始风险和历史评分保留。弹窗打开期间采集完成时暂缓刷新，任何弹窗关闭后在所有 Tab 同步顶部统计及当前页面，保留查询、分页和滚动位置。来源列表登录失效以橙色强调，与历史检查结果分开表达。以上不改变四种主状态、刷新恢复默认或后续工作台。 转项目弹窗截止时间未披露时统一显示“公告未明确”，参与校验不变。采集记录刷新重绘及分页保留未提交的来源搜索草稿、焦点和光标，仍按原已应用条件查询；只有查询或 Enter 才提交新文字，重置清空草稿，不新增持久化或改变刷新恢复默认逻辑。

## 9. 智能体后台架构

智能体属于后台能力，不直接作为一级菜单呈现：

- 总调度智能体：项目状态、流程进度和版本控制。
- 招标解析智能体：逐页解析、评分点和要求结构化。
- 可行性研判智能体：资格、企业能力、人员、业绩和材料缺口判断。
- 技术方案智能体：技术章节、架构、实施、服务和参数响应。
- 商务应答智能体：商务条款、资质、案例、人员和承诺材料。
- 智能检查智能体：覆盖率、合规、偏离、一致性和格式检查。
- 文档汇编智能体：目录、章节、表格、图片、版式和最终输出。

前台只呈现用户能够理解的业务状态，如“正在解析招标文件”“正在匹配企业案例”“发现 3 项材料缺口”。

## 10. 核心数据关系

```text
投标项目
  ├── 招标文件/附件/补遗版本
  ├── 招标条款
  ├── 资格项/评分点/商务要求/技术要求/格式要求
  ├── 投标事项与处理记录
  ├── 知识资产与证据引用
  ├── 标书目录与章节版本
  ├── 标书联合版本、检查批次与人工审核记录
  ├── 质检问题与整改记录
  └── 交付版本与归档记录
```

来源登录配置不要求所有网站提供账号。公开来源沿用原配置；需要登录时仅支持账号密码，通过来源检查验证登录，不提供人工登录授权或远程浏览器入口。密码输入默认隐藏，可切换显示；已有密码仅显示已设置，留空保留，换账号或网站域名后需重新填写。静态数据只保存账号展示值、密码设置标记、变更序号及登录状态，不保存输入的密码、Cookie、Token 或真实网站会话；真实产品需后端凭据托管及各站点登录适配，不使用用户本机浏览器的登录状态。扫码、短信、验证码及数字证书验证不在当前支持范围。公告可读但附件受限时说明范围，不判整个来源不可用，也不代办文件领取、购买或报名。登录状态随失效时间更新，执行前失效来源跳过且不生成记录，已启动任务遇到失效记录失败并保留完成的统计及原成功时间。旧人工授权配置转为待配置账号密码和待检查，旧登录有效状态不沿用，原配置摘要及采集历史保留。

## 11. 人工确认与安全边界

招标机会人工确认弹窗采用“先选择处理结果、再确认提交”：项目摘要后以单选项展示确认投标、放弃机会，备注选填；底部仅取消和确认。首次弹窗标题为人工确认，有处理结果后统一为重新确认并展示当前决定；均不默认选择，选择本身不保存。当前已放弃或已确认且无需重新确认的选项标注当前状态并禁用，避免重复提交；暂停、终止及投标截止时不能选择确认投标，仍可放弃。选择有效结果后才启用确认；弹窗版本、公告状态及截止时间校验继续生效，旧弹窗的查看最新内容入口放在正文提示区。取消、关闭、Esc 均不保存决定。

- 解析结果确认后才能作为后续编制基线。
- 资格不满足时不自动终止，由用户确认综合投标结论。
- 缺少知识来源时不得编造企业信息，必须显示材料缺口。
- 商务偏离、技术偏离、报价和关键承诺必须人工确认。
- AI 自动生成的量化指标必须标记来源或“待确认”。
- 正式导出前必须完成资格、组成、评分覆盖、偏离和格式检查。
- 项目知识沉淀前需要人工确认可复用范围。

## 12. 当前原型实现边界

当前原型实现：

- 登录页、首页、统一菜单和用户/消息交互。
- 招标机会列表和详情、筛选规则、来源验证及启停、计划/手动采集、部分失败及重试、分项初评、人工确认、文件补传及防重复转项目。
- 投标项目列表、新建项目，以及招标文件、解析结果、标书编制、质量审核、交付归档五个项目页签。
- 知识库分类、资料列表、人员档案、详情、上传解析和归档交互。
- 投标台账列表、归档详情、结果维护和项目复盘。
- 管理中心用户管理，包括新增、编辑、启用、禁用、删除和重置密码。

资格研判、响应处理建议和知识材料匹配统一整合在解析结果页；管理中心仅包含用户管理。
