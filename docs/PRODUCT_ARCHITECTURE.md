# 投标助手产品架构

## 1. 产品定位

投标助手是一套面向企业投标团队的全过程智能投标工作台。产品从用户主动创建投标项目、上传招标文件开始，通过招标解析、资格研判、知识匹配、响应策划、标书编制、智能检查、人工质量审核和文件交付，帮助团队完整、合规、可追溯地完成投标文件。

产品核心不是“一键生成一篇标书”，而是解决以下问题：

1. 招标文件是否看全、看准。
2. 企业是否具备投标资格，是否存在资格阻断问题。
3. 每一条招标要求和评分点是否都有响应内容及证明材料。
4. 标书内容是否来源可靠、前后一致、符合指定格式。
5. 最终投标文件是否完整、经过人工确认并可安全交付。

## 2. 产品范围

### 当前包含

- 首页
- 投标项目
- 知识库
- 投标台账
- 管理中心

### 当前不包含

- 招标机会
- 招标线索采集
- 线索管理
- 线索研判与转项目

产品入口固定为“新建投标项目”。

| 菜单 | 业务职责 |
| --- | --- |
| 首页 | 展示项目进度、临近截标、资格结论、材料缺口、待审核事项和知识资产预警 |
| 投标项目 | 完成招标文件上传、解析、研判、策划、编制、质检和交付 |
| 知识库 | 管理企业资料、资质、人员、业绩、方案、商务素材、模板和历史标书 |

| 管理中心 | 管理组织用户、权限、解析质检规则、输出模板、标签和系统配置 |

## 4. 投标项目工作台

投标项目是唯一的业务工作入口。进入具体项目后，采用以下项目内页签：

1. **项目概览**：项目基本信息、截止时间、阶段进度、负责人、重点问题、待办和最新版本。
2. **招标文件**：原始招标文件、附件、补遗、澄清文件、版本和差异对比。
3. **智能解析**：结构化提取招标要求，保留来源页码和条款原文。
4. **投标决策**：资格准入、不得存在情形、企业能力和材料缺口研判。
5. **响应策划**：评分矩阵、响应策略、任务负责人、计划完成时间和章节映射。
6. **知识匹配**：匹配资质、人员、案例、方案和证明材料，识别缺失与冲突。
7. **标书编制**：按招标目录分章节生成和编辑技术标、商务标等内容。
8. **智能检查**：由 AI 检查资格、评分覆盖、偏离、格式、数据一致性和阻断问题，问题在标书编制页内定位、整改和复检。
9. **质量审核**：人工只读查看已通过智能检查的技术标、商务标送审版本；审核前可退回标书编制，审核通过后开放交付归档，质量审核页隐藏退回操作并保留已通过状态。
10. **交付归档**：展示人工审核通过状态，保留退回修改入口；版本确认后导出 Word/PDF、生成文件包并归档。

### 标书版本规则

- 编辑过程使用自动保存的“工作稿”，自动保存不产生正式版本。
- 用户人工确认“保存为版本”时，同时锁定技术标和商务标，形成不可覆盖的联合版本快照。
- 版本号由系统按 `V1.0.x` 顺序生成，版本递增与智能检查次数相互独立。
- 智能检查、人工质量审核和正式交付必须绑定具体标书版本；存在未形成版本的工作稿修改时，不允许直接提交检查。
- 审核退回或交付退回后保留原版本、检查记录和审核结论，修改完成后另存新版本。
- 正式交付只使用一个人工审核通过版本；项目归档保留全部人工版本，知识库历史标书默认只沉淀正式交付版本。

## 5. 招标解析核心域

智能解析至少覆盖以下十个业务域：

| 解析域 | 关键输出 |
| --- | --- |
| 投标人须知前附表 | 截止时间、开标时间、保证金、有效期、签章、密封、递交方式等关键事项 |
| 资格审查/资格预审 | 资格准入清单、证明材料、企业匹配结果和缺口 |
| 投标人不得存在的情形 | 负面条件核查清单和所需承诺材料 |
| 投标文件组成 | 最终投标文件目录与完整性检查清单 |
| 评标办法 | 技术、商务、价格评分矩阵，分值、标准和响应策略 |
| 商务要求 | 商务条款响应事项清单 |
| 商务偏离表 | 商务要求、响应情况、偏离说明和人工确认状态 |
| 技术要求 | 功能、参数、实施、服务、交付和验收要求 |
| 技术偏离表 | 技术要求、响应参数、证明材料、偏离情况和人工确认状态 |
| 投标文件格式 | 指定章节、表格、承诺函、签章、页码、装订和文件命名要求 |

每条解析结果应保存：来源文件、页码/条款、招标原文、分类、重要性、强制性、分值、需要完成的内容、AI 置信度、人工确认状态。

## 6. 响应矩阵

响应矩阵是贯穿产品全流程的核心数据对象。每一条响应事项包含：

- 分类和编号
- 招标原文及来源位置
- 资格硬门槛/评分项/一般要求
- 分值和评分标准
- 需要完成的章节、表格或证明材料
- 响应策略
- 关联知识资产与证据
- 责任人和计划时间
- 当前状态和具体问题类型
- 最终标书章节位置
- 关联质检问题

状态建议统一为：待确认、待匹配、材料缺失、待编制、编制中、待审核、需整改、已完成。

## 7. 知识库架构

知识库保留多分类入口和左侧二级导航，方便按业务对象查找资料；除人员档案外，其他分类统一使用同一套资料列表、上传解析、详情和归档逻辑。分类只负责归类、筛选和限定 AI 检索范围，不再为每个分类设计独立的必填业务表单。知识库只维护资料，不设置审核流程。

### 企业资料

1. **企业基础资料**：营业执照、公司简介、财务、信用和开户信息。
2. **企业资质证照**：行业资质、体系认证、荣誉、知识产权和许可证。

### 人员资料

3. **人员档案**：先新增人员或批量导入人员名单，再批量上传资质资料，由 AI 解析姓名、证书信息并自动关联人员；未匹配和低置信度结果在导入前集中确认。
   - 证书与资质：以导入证书为入口，由 AI 自动提取证书名称、编号、机构和期限，用户可以修正解析结果。
   - 项目经历：以项目经历证明材料为入口，由 AI 提取项目、角色和参与期间。
   - 证明材料：以简历、学历和劳动关系等附件为入口，由 AI 提取相关信息。
   - 引用记录：记录人员档案被投标项目和标书章节引用的情况。

人员档案只按“在库、已归档”维护生命周期。在库人员可以编辑或归档，已归档人员可以查看或删除。人员详情中的证书与资质、项目经历和证明材料统一显示来源文件图标、资料名称和当前相关内容，并提供编辑、归档操作；已归档的关联资料进入统一的“已归档资料”列表，归档后可以删除。

人员档案不包含人员档期、项目占用或时间冲突管理。

### 项目经验

4. **业绩案例**：合同、验收证明和项目说明等历史项目资料。
5. **历史标书**：归档既往项目的技术标、商务标和最终交付附件，支持按项目类型查找和授权复用；知识库不承担复盘、得分、评委反馈或失分分析。

### 内容素材

6. **产品与技术方案**：产品介绍、功能、架构、实施、运维和安全方案。
7. **商务素材**：服务、保密、廉洁、售后和履约承诺。
8. **模板与格式**：投标模板、偏离表、简历、承诺函和封面目录模板。
9. **图表素材**：架构图、流程图、拓扑图、截图和组织架构图。

普通知识资料统一具备：名称、分类、类型、标签、摘要、说明、来源文件、AI 解析状态、最近更新和引用记录。上传资料后由 AI 自动提取通用信息和分类相关结构化信息；证书编号、发证机构、有效期限、项目金额等内容仅在原始资料中实际存在时解析和展示，不作为通用必填字段。

普通资料只保留简单的生命周期管理：在库资料由“已入库”和“解析中”组成，归档后进入独立的“已归档”列表。知识库不设置审核状态，也不设置“解析失败”状态；AI 未识别到有效结果时，直接展示空白基础属性，由人工补充后正常入库。编辑资料时可以修改属性或替换来源文件并重新解析，不再提供独立的“上传新版本”入口。在库资料可查看、编辑和归档；已归档资料可查看或永久删除，删除操作仅对已归档资料开放。知识库不维护资料使用范围或查看权限字段。

有效期是独立于资料生命周期的业务维度，只保留“长期有效”和“固定有效期”两种类型：没有明确截止日期的资料统一视为长期有效，证照、人员证书以及需要定期更新的证明资料统一按固定有效期维护。系统根据 AI 提取的截止日期按 60 天口径计算“有效、临期、已过期”等状态，并在总览指标、有效期预警 Tab、左侧分类目录、资料列表和详情中集中提醒。已过期资料仍保留在库并提示通过编辑替换文件；已归档资料保留有效期记录，但不计入当前预警数量。

知识库中代表具体文件的图标统一复用公共文件格式图标，根据真实扩展名显示 PDF、Word、Excel、PPT、压缩包、SVG、图片、OFD 等格式；人员头像和上传、编辑、归档等操作图标继续表达人员或操作语义，不与文件格式图标混用。

## 8. 标准业务流程

```text
新建投标项目
  → 上传招标文件及附件
  → AI逐页解析并形成要求清单
  → 人工确认解析基线
  → 资格审查与投标研判
  → 人工确认继续投标
  → 知识匹配与材料缺口补充
  → 评分响应策划与任务分工
  → 技术标、商务标等并行编制
  → 人工保存标书联合版本
  → AI智能检查与问题整改
  → 提交人工质量审核
  → 人工查看技术标、商务标送审版本
  → 人工审核通过
  → 生成Word、PDF及交付文件包
  → 全部标书版本归档、投标台账与知识沉淀
```

## 9. 智能体后台架构

智能体属于后台能力，不直接作为一级菜单呈现：

- 总调度智能体：项目状态、任务编排、进度和版本控制。
- 招标解析智能体：逐页解析、评分点和要求结构化。
- 可行性研判智能体：资格、企业能力、人员、业绩和材料缺口判断。
- 技术方案智能体：技术章节、架构、实施、服务和参数响应。
- 商务应答智能体：商务条款、资质、案例、人员和承诺材料。
- 智能检查智能体：覆盖率、合规、偏离、一致性和格式检查。
- 文档汇编智能体：目录、章节、表格、图片、版式和最终输出。

前台只呈现用户能够理解的业务状态，如“正在解析招标文件”“正在匹配企业案例”“发现 3 项材料缺口”。

## 10. 核心数据关系

```text
投标项目
  ├── 招标文件/附件/补遗版本
  ├── 招标条款
  ├── 资格项/评分点/商务要求/技术要求/格式要求
  ├── 响应事项与任务
  ├── 知识资产与证据引用
  ├── 标书目录与章节版本
  ├── 标书联合版本、检查批次与人工审核记录
  ├── 质检问题与整改记录
  └── 交付版本与归档记录
```

## 11. 人工确认与安全边界

- 解析结果确认后才能作为后续编制基线。
- 资格不满足时不自动终止，由用户确认投标决策。
- 缺少知识来源时不得编造企业信息，必须显示材料缺口。
- 商务偏离、技术偏离、报价和关键承诺必须人工确认。
- AI 自动生成的量化指标必须标记来源或“待确认”。
- 正式导出前必须完成资格、组成、评分覆盖、偏离和格式检查。
- 项目知识沉淀前需要人工确认可复用范围。
