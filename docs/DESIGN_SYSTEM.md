# 投标助手设计体系

## 1. 设计方向

视觉参考 `E:/Cursor/smart-query-prototype`，延续浅色科技蓝体系：

- 白色和浅灰蓝作为主要页面背景。
- 高饱和科技蓝承担主操作和进行中状态。
- 深蓝承担标题和品牌识别。
- 青色只作为高光，不大面积使用。
- 红、橙、绿分别用于阻断/失败、临期/待确认、完成状态。

整体应专业、可信、规整，避免过度炫技和大面积深色背景。

## 2. 核心颜色

| 变量 | 色值 | 用途 |
| --- | --- | --- |
| `--primary` | `#1677ff` | 主按钮、选中菜单、进行中状态 |
| `--primary-dark` | `#0b3d91` | 品牌、重点标题 |
| `--primary-accent` | `#55c7ff` | 渐变高光 |
| `--primary-soft` | `#eaf3ff` | 选中背景、轻提示 |
| `--bg` | `#f4f7fb` | 页面背景 |
| `--heading` | `#102a48` | 标题 |
| `--text` | `#1f2937` | 正文 |
| `--muted` | `#64748b` | 辅助说明 |
| `--green` | `#16a34a` | 完成、合格 |
| `--orange` | `#f59e0b` | 临期、待确认 |
| `--red` | `#ef4444` | 阻断、失败 |

不得在单个页面重新定义一套主色。

## 3. 字体与层级

- 字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", Arial, sans-serif`。
- 页面主标题：24-28px，字重 800。
- 卡片标题：16-18px，字重 700-800。
- 正文：14px。
- 辅助说明和表格次要信息：12-13px。
- 数据指标：26-32px，使用等宽数字特性。

## 4. 圆角与阴影

- 小标签：8px 或胶囊形。
- 按钮：10px。
- 输入框：12px。
- 卡片：16px。
- 主要容器：18px。
- 登录卡片：22-24px。
- 阴影保持克制，优先使用细边框和浅阴影构造层级。

## 5. 组件约定

### 按钮

- 功能按钮统一为图标+文字。
- 主按钮每个操作区原则上只出现一个。
- 危险操作使用红色文字或危险样式，并要求二次确认。
- 纯图标按钮仅用于通知、关闭、显隐密码等明确控制，必须提供可访问名称。

### 文件格式图标

- 所有代表具体文件的图标统一使用公共 `BiddingFileIcons` 映射，根据扩展名显示 PDF、DOCX、XLSX、PPTX、ZIP、SVG、PNG、OFD 等格式标记。
- 文件格式图标用于列表、上传结果、附件和详情来源文件；人员头像、证书类别和上传、编辑等操作仍使用对应的业务或操作图标。
- 未知格式显示真实扩展名，不能用统一文档图标掩盖文件格式。

### 标签

- 蓝色：进行中、待处理。
- 绿色：已完成、已通过、材料有效。
- 橙色：待确认、临近截止、证书临期。
- 红色：阻断、不满足、已过期。
- 灰色：未开始、已归档。

### 卡片

- 卡片标题左对齐，操作区右对齐。
- 卡片之间使用 16px 间距。
- 同一行卡片保持等高、内容对齐。
- 关键问题不依赖颜色单独表达，必须同时提供文字或图标。

### 表格

- 行高 56-64px。
- 项目名称等长文本左对齐，状态和数字按内容居中或右对齐。
- 操作列保持紧凑，按钮使用图标+文字。
- 表格在常见桌面宽度下不得横向溢出。

### 弹层与下拉

- 遮罩使用透明深蓝灰。
- 弹窗标题、正文和底部按钮区清晰分层。
- 用户菜单、消息面板由公共框架统一提供。

## 6. 页面框架

- 顶部导航高度 64px，吸顶。
- 品牌区在左、一级菜单居中、通知和用户区在右。
- 页面主体最大宽度 1540px，左右留出至少 16px 安全间距。
- 首页沿用最初的欢迎区和单行五项指标，中部为“机会与项目双 Tab / 按时间排序的人工待办”，底部为“八节点投标全流程 / 业务提醒”。上下两行共用同一套约 7:3 分栏，同排卡片等高、标题和内边距统一；两个 Tab 共用固定四条预览高度，切换不改变卡片结构。继续复用共享导航、卡片和主题变量。
- 项目详情统一使用招标文件、解析结果、标书编制、质量审核、交付归档五个项目内页签，不新增另一套全局菜单。

## 7. 动效

- hover 和弹层过渡控制在 160-220ms。
- 只使用轻微位移、阴影和透明度变化。
- AI 执行状态可以使用脉冲或流动高光，但不得影响正文阅读。

## 8. 文案与示例数据

- 使用真实投标语境，如资格审查、评分点、偏离表、标书编制、截标时间。
- 问题文案明确说明对象和后果，不使用模糊的“存在异常”。
- AI 状态说明正在处理什么、当前进度和下一步需要用户做什么。
- 示例日期、项目状态、进度和待办必须互相一致。
